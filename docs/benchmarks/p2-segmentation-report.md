# P2 切段校準報告

執行日期：2026-09-19。狀態：**切段問題已解決；剩餘錯誤屬模型層。**

## 素材

使用者以 `examples/mic_stream.py --save-wav` 錄的 10 句真實口語（MacBook Pro 內建麥克風、
75 秒、含句間停頓與一段刻意的長句）。音訊與事件留在使用者機器上，不進 Git；
重跑用 `uv run python benchmarks/replay_segmenter.py <take>.wav --transcribe`。

錄下的是**實際送給 server 的 PCM**，所以 replay 的 sample 範圍與當時的事件可直接對照，
換參數不必請使用者重講。

## 校準前發現的兩個缺陷

**一、開頭掉字。** 10 句裡有 2 句掉了第一個詞（「這個 PR…」→「PR…」、「明天的會議…」→「在會議…」）。

根因不是 pre-roll 數值太小，而是 `_trim()` 在靜音狀態只保留 `next_sample - pre_roll`。
語音是**回溯確認**的（要先累積 `min_speech_ms` 才確認），等到確認時該保留的 pre-roll 已經被裁掉，
`_confirm()` 再被 `buffer_start` 夾住，實際 pre-roll 縮到接近 0。

驗證方式：把同一段音訊多給 0.6 秒前置直接送模型，「這個」與「明天的」都回來了——
證明是收音端被切掉，不是模型認不出來。

修法：
- `_trim()` 在靜音狀態保留 `pre_roll + min_speech + slack`，讓回溯確認有東西可用。
- 確認語音後從 candidate 往回走過仍高於 `onset_threshold=0.2` 的 window，找到真正的起點，再套 pre-roll。
- `pre_roll_ms` 200 → **600**。實測 200 ms 掉字、600 ms 完整。中文的送氣/擦音起頭（「這」「明」）能量爬得慢。

**二、長句硬切造成重複字。** 8 秒上限切在「人力規劃」中間，模型把被切斷的詞在兩側各補完一次：
第 9 段結尾出現「…明年的人力規劃。」，第 10 段又是「人力規劃。」。

修法：
- 到上限時先在最近 `split_search_ms=1200` 內找最安靜的 window 切，而不是硬切在當下。
- 找不到夠安靜的點就再等 `split_grace_ms=2000`，真的超過才硬切，所以片段的實際上界是
  `max_segment_ms + split_grace_ms`。
- 切點必須至少保留目標長度的一半，避免在片段開頭附近削出一小條。
- `max_segment_ms` 8000 → **12000**。多數人遠在 12 秒前就會停頓，上限因此很少觸發，
  改由自然靜音收段；這是偏離 [03](../03-architecture.md) 初始值的校準結果。

## 校準後結果

10 句 → 10 段，boundary 全為 `silence`，沒有掉字也沒有重複字。

| 指標 | 結果 |
|---|---:|
| 正規化後 MER | **3.97%**（6/151） |
| 完全正確的句子 | 5/10 |
| 私用區字元出現率 | 9/10 |

真實口語的 MER 比朗讀語料的 4.92% 還低。剩下的 6 個錯全是模型替換，切段改不動：

| 參考 | 辨識 | 類型 |
|---|---|---|
| tag 一個 release | take 一個 release | 英文近音 |
| 新台幣 | 新臺幣 | 異體字，可接受 |
| 不是姿勢 | 不是知識 | 同音詞消歧失敗 |
| 林佳蓉 | 林嘉蓉 | 人名同音字 |
| 再看這一季 | 再跟這一季 | 近音替換 |

極短詞「好」「對」都正確收到，`min_speech_ms=160` 不需要調。

## 未驗證

- 只有一位語者、一個麥克風、一次錄音。多語者、遠場、吵雜環境都沒測。
- 會議級長時間連續語音（60 分鐘）沒測，`max_segment_ms=12000` 對持續獨白的影響未知。
- 私用區字元仍是 P0 的封鎖問題，見 [P0 品質報告](p0-quality-report.md)。
